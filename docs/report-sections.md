# Report Sections

The Collapsible Report Kit is a report surface, not a planning framework. These sections are defaults for an implemented report; teams can rename, remove, or add sections without adopting any particular planning process.

## Default implemented-report sections

1. **Overview** — what changed, why it matters, current status, and top-level outcome.
2. **Scope and approvals** — the approval state for this report or bundle: approved, draft, readiness, or implemented. If no planning framework is used, this can simply state who requested the report and what boundary it covers.
3. **Implementation summary** — concrete work performed, grouped by component, workflow, or deliverable.
4. **Reuse and provenance** — what existing assets, templates, components, prior reports, libraries, or patterns were reused; what was newly created; and where each came from.
5. **Validation evidence** — tests, smoke checks, screenshots, public readbacks, source links, and concise evidence summaries.
6. **Artifacts and deliverables** — HTML, PDF, bundle files, deploy URLs, source paths, and manifest references.
7. **Risks and next actions** — known gaps, owner decisions, residual risks, and follow-up tasks.

## Optional sections

- **Decision log** — useful when a report records multiple human choices.
- **Change log** — useful when a report has several revisions.
- **Appendix** — useful for long evidence summaries that should not interrupt the main reading path.

## What belongs elsewhere

A full planning method, approval workflow, estimation scale, or agent execution protocol should live in a separate library. This kit can display a plan or approval status, but it should not force teams to adopt one specific planning system.
